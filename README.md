### 5.6.8 这一版：标准库外科手术（APK -906 KB）

核心代码已经压到头，这一版对内置 CPython 标准库动刀：

- **删掉的**：`unittest/`、`doctest.py`、`pydoc.py` + `pydoc_data/`、`venv/`、`turtle.py`，
  以及依赖 pydoc 的 `cgitb.py` / `xmlrpc/`。（`tkinter turtledemo ensurepip lib2to3 idlelib
  distutils` 本来就不在这个包里。）
- **洗掉的**：剩下 494 个 `.py` 去掉全部注释、空行、docstring（`ast` 定位 docstring，
  `tokenize` 去注释/空行，每个文件 `compile()` 校验，失败就保留原文件）；`this.py` 原样保留。
- **结果**：`stdlib.tar.xz` **1,688,784 → 793,312 B（-53%）**，解压后 **12 MB → 6.2 MB**，
  APK **10,156,396 → 9,249,903 B（8.82 MiB）**。
- **验证**：`compileall` 全过；用裁剪后的目录启动宿主 Python 3.12，59 个常用模块导入 + json/re/
  hashlib/pathlib/tempfile 实跑通过。注意 `asyncio/decimal/fractions/statistics` 依赖
  `_contextvars`，这个 C 扩展本来就没编进 `libcpython`，裁剪前就导入失败。
- 打包脚本 `tools/pack_stdlib.py`（GNU tar + LZMA2 preset 6，和原来 `tar cJf` 格式一致）。

### 5.6.7 这一版：关掉「启用多区域」后的三个收尾

5.6.6 里关掉开关会立刻拆成单区（这是开关本身该做的事），但顺着 `files/zone.txt` 查出三个问题：

- **单区状态存不下来**：单区没有分隔线（0 段），`saveLayout` 直接返回 null，日志是
  `save desync … why=no segs`。现在 ZL2 允许 0 段，单区也能正常落盘。
- **恢复时读错字段**：`restoreZones` 把 ZL2 的第 4 个字段（段数）当格子数，2/3/5 个区会被误判成
  「区数不一致」退回网格（4 区时 4 段恰好相等，所以没暴露）。改用 `PaneCodec.decode().n`。
- **关掉开关不再丢布局**：关掉时不 clean、也不落盘单区状态，并把多区布局备份到
  `zone_multi_state/zone_multi_panes`；重新打开「启用多区域」后，**下次启动**自动恢复上次的多区布局。
  设置里的提示也改成这句。

`PaneTilingTest` 35 → **36**（单区 0 段快照往返）。

### 5.6.6 这一版：多区「重开粘一块」修复 + 「启用多区域」开关

- **重开分区两两线粘一块**：2×2 摆成十字后重开，上下两根竖线 / 左右两根横线被合并成一条，
  拖一段整列都动。根因不是 5.6.5 改坏了（Java 与 5.6.4 逐文件相同），而是 5.6.1 起快照只存坐标，
  恢复时按坐标取段 —— **新建不合并、重开才合并**。
  现在快照改成 **ZL2**（段表 + 每格四个段下标），同坐标的不同段是不同对象；旧 ZL1 快照恢复时
  按「格子覆盖范围」自动拆回（2×2 → 4 段，合并单元格保持共享）。
- **设置 → 多区布局 → 「启用多区域」**（默认开）：关掉后回到主界面强制单区 —— 除第一个区外
  全部关闭、清掉记住的分区、隐藏 `+`；启动时也不再恢复多区布局（直接打开上次的文件）。
- `PaneTilingTest` 27 → **35**（ZL2 往返 / 同坐标两段独立 / 坏数据拒绝 / 拆分规则）。

### 5.6.5 这一版：libc++ 改为静态链接（安装包 -1.27 MiB）

`lib/arm64-v8a/libc++_shared.so`（1,423,696 B，占 APK 12%）已删除，libc++ / libc++abi / libunwind /
compiler-rt 全部静态链进 `libpyedit.so`（179,040 → 273,720 B）。**C++ 源码一行没改**，只换了链接方式。

- 静态库来自 **NDK r30**（clang 21，与项目 libc++ 头文件同版本、同为 `__ndk1` ABI）；
- 产物必须带 `NEEDED libc.so / libm.so / libdl.so` —— 5.6.5 第一次装机就是因为只 NEEDED 了 libdl、
  解析不到 `__sF` 直接闪退（旧版是靠 `libc++_shared.so → libc.so` 的依赖链才找到 libc 符号的）；
- `build.sh` 改用 `-z defs` 链接，并断言 NEEDED 三件套 + 静态 C++ 符号，少一个就构建失败；
- 47 个 JNI 导出与旧版逐字节一致；单测 90 + 91 + 49 + 31 + 13 + 27 全过。

## 1. 这是什么

YHHYPy 不是「把桌面 IDE 塞进手机」，而是按手机的交互重做的一套编辑器：

- **编辑器完全自绘**（不用 `EditText`）：滚动、彩色文本、行号、补全、波浪线都不会卡；
  词法高亮、符号索引、折叠、语法检查的核心算法用 **C++** 写，通过 JNI 调用。
- **内置完整 CPython 3.12.8**（独立进程）：`input()` 可交互、死循环可随时停止；
  还带一个纯 Python 的 **pip 包管理器**（PyPI wheel 安装、依赖树、批量卸载）和
  **手机本地编译 C 扩展**（单文件 `.c` → `.so`，配合 Shizuku）。
- **自由多区**：一个区可以是编辑区、终端（Shell）或解释器（REPL），最多 6 个，
  分割线可以随意拖、吸、挤掉；**关掉软件再打开会原样恢复**。
- **界面可玩**：15 类记号逐项配色 + 粗体/斜体、5 套预设 + 任意多个自定义主题、
  等宽/无衬线/衬线/载入 `.ttf`、行分隔线、彩虹缩进参考线、右侧大纲 MiniMap、行尾 CodeLens。
- **零第三方 UI 依赖**：不用 Gradle、不用 AndroidX；构建脚本自己调 aapt2 / javac / R8 / apksigner，
  自己写 16 KB 对齐的 APK 打包器。

## 2. 编辑区

### 2.1 语法高亮（15 类记号）

关键字 / 内置函数 / 常量 / 字符串 / 注释 / 数字 / 运算符 / `def` 名 / `class` 名 / 装饰器 /
`self` / 参数 / 自定义函数 / 自定义类 / 普通文本。
三引号字符串支持跨行；每一类都可以单独设字体颜色与 **B/I**。

### 2.2 智能补全

- 输入字母、`_`、`.` 自动弹出；点选插入，`Tab` / 回车选第一个，方向键上下移动。
- 每行增量提取符号：`def` / `class` / 赋值左值 / 参数 / `for` 目标 / `as` / `import` /
  `self.xxx` 属性，再合并 Python 关键字、内置函数、常量。
- 排序：**精确 > 前缀 > 忽略大小写前缀 > 子串 > 子序列**，带类型标签。
- `.` 之后按属性补全。

### 2.3 语法检查（24 类，原生 C++）

括号 / 冒号 / 引号未闭合、缩进、赋值目标（`4 = 1`、`if x = 1:`）、缺右值、
关键字当函数名（`def return()`）、参数重名 / 默认值顺序、调用参数顺序、import、
数字字面量（`012`、`1.2.3`、`0b102`）、模块级 `await` / `yield`、孤立 `else` / `except`、
`type` 缺 `=`、f-string、`except*`、单行字符串未闭合等。
规则对齐 CPython；错误处画红色波浪线，状态栏显示数量，点开可看明细并跳转。
开启时 260 ms 防抖，同一 revision 不重复检查。

### 2.4 代码折叠

- 传统 `if / for / while / try / with / def / class` 块折叠。
- **多行 / 单行的 `list` / `dict` / `tuple` / `set` 字面量折叠**（类型推断）。
- `else / elif / except / finally / case` 子句可单独折叠；展开会连带外层。
- 抽屉「折叠 ▸」：折叠所有 / 折叠关键字 / 折叠多行赋值和函数 / 展开全部。
- 折叠摘要按 token 上色，保持原缩进。

### 2.5 代码透镜（行尾标注 / CodeLens）

- 函数行尾显示 **被使用 N 次**，点击打开查找并填好名字。
- `class` 行显示 **N 个属性 · M 个方法**；集合字面量行尾显示类型。
- 右侧 MiniMap 只画色块 / 错误红点 / 可见框，打开时**挤压**编辑区而不是遮盖正文。

### 2.6 选区手柄与编辑操作

- 选中文字后两端出现圆形手柄，拖动精确调整；拖到屏幕上下边缘自动滚动，
  松手后复制 / 剪切工具条自动回来。
- 撤销 / 重做（按输入批次合并），缩进 / 反缩进，自动缩进与括号 / 引号配对，
  长按选词、点行号选整行，菜单全选 / 复制 / 粘贴。
- **行分隔线**：每行下沿一条细横线（颜色可调，滚动 / 折叠不错位）。
- **彩虹缩进参考线**：按代码块层级渐变，首尾颜色可自定义。
- 光标 / 当前行 / 选区 / 错误线颜色都可配；字号、行距、字体族（含载入 `.ttf`）。

### 2.7 查找 / 替换

常驻底部查找栏：正则、跨行（`\n`）、分组引用（`$1`）、替换 / 全部替换，
全部替换只需一次撤销即可恢复；点状态栏的问题数也能跳到出错行。

### 2.8 多文件

- 打开 / 保存 / 另存为 / 最近文件，走系统文件选择器（SAF），**不需要存储权限**。
- 左侧抽屉列出「打开的文件」，点一下切到该文件；多个编辑区时进入「点哪个区替换哪个」。
- 非 `.py` 文件（txt / json / xml / js…）自动降级为纯文本模式，仍然极速。
- 切到后台自动保存（可关）；退出时若有未保存修改会提示。
- 代码片段：内置 21 个高亮片段，支持 `${cursor}` 光标落点，可编辑 / 新增。

## 4. 运行 / 解释器 / 终端 / 包管理

### 4.1 运行（CPython 3.12.8）

- 独立进程运行当前文件，`input()` 可交互；有「停止」按钮，死循环也能掐掉。
- 输出面板可展开 / 收起；`▶` 跑**焦点编辑区**的文件（焦点在终端/解释器上时跑最后一个编辑区）。
- 解释器（REPL）就是「一个区」：`+ → 解释器`，可以和多份代码并排。

### 4.2 终端（Shizuku / root / 本应用身份）

- 优先 Shizuku（uid 2000），其次 root，最后退回应用自身身份；标题栏显示当前身份。
- 作为区存在：大小由分割线决定，可清屏 / 关闭。

### 4.3 包管理器（纯 Python）

- 从 PyPI 安装 **纯 Python wheel**，解到应用内 `dist-packages`，可 `import`。
- 按 `Requires-Dist` 自动装依赖（不解析版本冲突），显示依赖树、支持批量卸载。
- 安装前做纯 Python 校验（不打包二进制扩展）；可「装完试跑」验证。
- **C 扩展编译**：单文件 `.c` → `.so`（Shizuku + 已配置的编译器 / 头文件包），可被 Python `import`。

## 9. 已知限制

1. 仅 **arm64-v8a**，不支持 32 位 / 模拟器。
2. CPython 未编译 `ssl`：Python 层的 HTTPS 不可用（装包下载由 Java 层接管）。
3. `pip` 不解析版本约束 / 冲突，只装纯 Python wheel。
4. 语法检查是轻量结构检查，不是完整 Python 语法分析（不做 AST）。
5. C 扩展编译只支持单文件 `.c`（不支持 C++ / 多文件 / setup.py）。
6. 折叠基于缩进，极端怪写法（`x = 1; else:`）不保证正确。
7. 多区上限 6 个；某个方向拖不动是几何约束在保护布局（再拖就会穿透）。
8. 多区「合并单元格」的构图不做拆段，拖动时可能整条线一起动（但保证不穿透、不留空洞）。
9. 分区记忆只恢复位置 / 类型 / 文件 / 光标：终端与解释器的历史输出不保存，
   没有保存过的新文档恢复后是空的 `未命名.py`。
10. 旋转屏幕不会自动重排（恢复时按比例缩放）。
11. 装包必须手动点（本仓库不发自动更新）。

## 10. 构建（开发者）

```bash
./build.sh
# 产物：dist/PyEditor.apk
```

依赖：clang-19、Android sysroot + libc++ 头文件、**NDK r30 的静态 libc++**
（`/opt/asysroot/ndk-r30-clibs/`：`libc++_static.a`、`libc++abi.a`、`libunwind.a`、
`libclang_rt.builtins-aarch64-android.a`，以及 `libc.so/libm.so/libdl.so` 的链接 stub）、
JDK 17、`/opt/android-sdk/build-tools-tmp`（d8 / apksigner）、aapt2（arm64 原生）。流程：
clang 交叉编译 `libpyedit.so` → aapt2 处理资源 → javac（bootclasspath 用 API 30 android.jar）
→ d8 + R8 混淆 → 自写 `tools/pack.py` 按 `resources.arsc` 4 字节、`.so` 16 KB 对齐重新打包
→ apksigner 签名（v1+v2+v3）。

> 路径含中文时，javac 前需要 `export LC_ALL=C.UTF-8`（build.sh 已内置）。
